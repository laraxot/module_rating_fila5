# 18.58 — Valore export XLS riusabile sul rating

## Perché

`getValueHtml()` (PDF) sa già: se il criterio ha figli, `pivot.value` è l’id del
figlio e va mostrato il suo testo. L’export Excel ha lo stesso bisogno ma
**plain text** (niente HTML Money/RichEditor).

La logica deve vivere sul modello Rating, non nei Resource host: ogni host
(IR, eventualmente Ptv/Performance) riusa path + accessor.

## Contratto

### `BaseRating::resolveSelectedChild(): ?self`

- Solo se `hasChildRatings()` e `pivot.value` valorizzato.
- Preferisce `children` già caricati (`firstWhere('id', …)`); altrimenti query
  `find` (fallback, da evitare in export grazie a eager load).

### Accessor `xls_export_value` (`getXlsExportValueAttribute`)

| Caso | Valore |
|------|--------|
| Figlio trovato | `strip_tags(txt ?? title)` |
| Ha figli ma value vuoto / figlio assente | `''` |
| Foglia | `pivot.value` (numerico o null) |

### `HasRatingsTrait::ratingXlsValuePath(BaseRating $rating): string`

`ratings_by_id.{id}.xls_export_value` — unico path `data_get` per la colonna
valore in export (foglia o padre).

`ratingValuePath($rating, 'note')` resta per la colonna note.
