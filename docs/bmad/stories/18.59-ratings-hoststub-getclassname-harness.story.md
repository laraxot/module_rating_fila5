# 18.59 — Harness `getClassName` nei test ratings_by_id

## Perché

`getRatingsByIdAttribute()` crea un `Rating` minimo via `Rating::getClassName()`
quando il pivot esiste ma il model non è in `ratings` (story 18.56/18.57,
model_type doppio). Nei unit test il backtrace di `getClassName()` non risolve
il caller → `RuntimeException: Unable to resolve caller object for getClassName()`.

Due casi in `HasRatingsTraitRatingsByIdTest` falliscono ancora (ratings vuoti +
solo `ratingMorphs`). Note in 18.56 e IR 5.160: «da tracciare a parte» — questa
è quella story.

## Obiettivo

Harness stabile (stub / binding / force morph class) così i test pivot-only
passano **senza** DB e senza dipendere dal backtrace di produzione.

## AC

- [ ] I due test pivot-only di `HasRatingsTraitRatingsByIdTest` passano
- [ ] Nessun cambiamento al comportamento runtime di `getClassName()` in app
- [ ] Documentato in `RatingsHostStub` (o fixture dedicata) il contratto del harness
- [ ] PHPStan Rating OK; Pest suite ratings_by_id verde

## Non-goals

- Riscrittura di `XotBaseModel::getClassName()`
- Cambiare la logica di merge pivot / alias model_type
