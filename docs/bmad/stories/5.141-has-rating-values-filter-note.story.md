## Perché

Con il contratto «altro» (`value = null` in DB + `note` filled), la definizione attuale di «valutata» in `HasRatingValuesFilter::constrainToValued()`:

```php
$rows->whereNotNull('value')->where('value', '!=', 0);
```

classifica come **non valutate** schede dove il valutatore ha compilato solo testo libero. Bug di prodotto, non di UI.

## Decisione preferita (KISS) — opzione (a)

«Valutata» = esiste almeno una riga pivot con:

- `value IS NOT NULL AND value != 0`, **oppure**
- `note IS NOT NULL AND note != ''`

Opzione (b) sentinel numerico in `value` → **scartata** (rompe colonna numerica / getTot / coerenza con null).

## Codice proposto (to-be)

File: `Modules/Rating/app/Filament/Tables/Filters/HasRatingValuesFilter.php`

```php
protected function constrainToValued(Builder $rows): void
{
    $rows->where(static function (Builder $q): void {
        $q->where(static function (Builder $numeric): void {
            $numeric->whereNotNull('value')->where('value', '!=', 0);
        })->orWhere(static function (Builder $withNote): void {
            $withNote->whereNotNull('note')->where('note', '!=', '');
        });
    });
}
```

Aggiornare il docblock di classe: «valutata» non è più solo value numerico non-zero.
