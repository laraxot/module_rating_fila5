# 5.229 — `HasRatingsTrait::ratingXlsFields` → `RatingData::getXlsFields`

## Perché (architettura)

1. `RatingData` è il data layer del dominio rating — `getXlsFields`
   (contratto del sistema Xot exporter) ci appartiene.
2. `HasRatingsTrait` è un god-object (~700 righe): relazioni, mutatori,
   form, export. `ratingXlsFields` non è relazionale → non è sua casa.
3. Il wrapper attuale `RatingData::getXlsFields → HasRatingsTrait::ratingXlsFields`
   è un'indirezione inutile ( doppia SSoT).
4. `getXlsFields` è il nome canonico del contratto export (XotBaseExporter).
   Toglierlo dal trait evita il collision warning con il contratto Resource.
5. Firma con `$ratingClass` esplicito = onesta (il default `Rating::getClassName()`
   lancia `RuntimeException` in contesto statico — documentato come trappola).

## Analisi contro-verifica (metti tutto in discussione)

| Claim | Verifica |
|-------|----------|
| "RatingData è il posto giusto" | **Forte**: è già il data layer del rating, ha `updateColumns`, `fromArray`. L'aggiunta è coerente. |
| "Il trait è solo relazioni" | **Falso oggi**: contiene anche `ratingFormFields`, `formFieldLabel`, `ratingXlsValuePath`, `ratingObjectives`, `syncRatingsWhere`. |
| "Spostare risolve il god-object" | **Parziale**: un metodo su ~700 righe, ma il pattern è la cura giusta. |
| "User API `RatingData::getXlsFields`" | **Valida**: firma statica, `$ratingClass` esplicito, testabile senza istanza. |
| "getClassName risolve da static" | **Falso**: documentato come trappola — `ratingClass` required. |
| "RatingData ha già 2 concetti" | **Vero**, ma questo è il terzo: è un debito esistente, non da peggiorare a 4. |
| "formFieldLabel/ratingXlsValuePath restano nel trait" | **Ribaltato in [5.232](./5.234-ratingdata-ratingclass-required-revert-backtrace.story.md)**: l'argomento "layout host" non regge — nessuno dei due usa `$this`, sono funzioni pure di `$rating`; e chiamarli via `HasRatingsTrait::metodo()` è la violazione che 5.232 vieta a prescindere dal dominio. |

## Fix

1. `RatingData::getXlsFields(array $where, string $ratingClass): array` — corpo pieno
   (query + reject + load + map), nessun delega.
2. `HasRatingsTrait::ratingXlsFields` — rimosso (o wrapper thin che chiama `RatingData::getXlsFields` se serve compatibilità).
3. `IndennitaResponsabilitaResource::getXlsFields` — già usa `RatingData::getXlsFields($where, Rating::class)`.
4. Aggiornare docs: `rating-xls-fields-reusable.md` (§6 stato swarm), `form-field-label-and-xls-path-home.md` (verdetto), `5.179`, `18.60`, `5.228`.
