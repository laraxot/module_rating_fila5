# 1.1: Create Scheda

**Story ID:** 1.1
**Epic:** 1 — Scheda Management Workflows
**Slug:** create-scheda
**Status:** backlog

## Story

As an evaluator,
I want to create, view, edit (while in draft), and delete a Scheda evaluation record for an employee,
so that I can record performance scores with validated, structured data before submitting it.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. Evaluator can create a new Scheda via a Filament form with fields: employee (select), evaluation_type (Individuale | Dirigente), year, and per-criterion scores.
2. Form rejects submission when any required field is missing, `year < 2020`, or any score is outside `[1, 10]`; validation errors display inline on the offending field.
3. On successful creation, the Scheda is persisted with `status = "draft"`, `created_at`/`updated_at` set to now, and `approved_at = null`.
4. Evaluator can open, edit, and save a Scheda while `status = "draft"`.
5. Evaluator can delete a Scheda while `status = "draft"`; delete marks the record soft-deleted (`deleted_at` set) rather than removing the row.
6. SchedaResource create/edit/delete actions are gated behind a `SchedaPolicy`; an unauthenticated user is denied access to the resource entirely (full role-matrix enforcement ships in Epic 3, story 3.1 — this story wires the policy class and a default-authenticated-only gate).

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

- **Unit:** `Scheda` model casts (`scores` array, `approved_at` datetime), `SoftDeletes` trait present, default `status` behavior at model level.
- **Feature (Pest):** create with valid data succeeds and lands in `status=draft`; create with `score = 11` or `score = 0` fails validation; create with `year = 2019` fails; create with `year = 2020` succeeds (boundary); edit while draft persists changes; delete marks `deleted_at` without removing the row; guest/unauthenticated access to the resource is denied.
- **Fixtures:** `SchedaFactory` producing valid draft records tied to a `User` factory (representing the evaluated employee) with `tenant_id` set.
- **Edge cases:** missing employee selection, invalid `evaluation_type` value (not in enum), score boundary values (1 and 10 valid; 0 and 11 invalid), missing required score.
- Tenant-isolation/RLS assertions are explicitly deferred to Epic 3 (3.5, 3.8); this story's tests run within a single tenant context.
