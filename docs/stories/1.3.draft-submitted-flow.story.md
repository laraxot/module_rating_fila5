# 1.3: Draft → Submitted State Flow

**Story ID:** 1.3
**Epic:** 1 — Scheda Management Workflows
**Slug:** draft-submitted-flow
**Status:** backlog

## Story

As an evaluator,
I want to explicitly submit a completed draft Scheda,
so that it moves out of the freely-editable draft state and becomes ready for manager sign-off.

## Acceptance Criteria

<!-- LOCKED. External dev tools must not edit Acceptance Criteria. -->

1. `Scheda.status` is constrained to enum values `draft`, `submitted`, `approved`, with `draft` as the default on creation.
2. Evaluator can transition a Scheda from `draft` to `submitted` via a "Submit" Filament action, available only when `status = draft` and all required scores are filled in.
3. Submitting is rejected (action disabled, or a validation error if forced) when any score is missing or out of range `[1, 10]`.
4. Once `status = submitted`, the standard `EditScheda` form no longer allows changing scores/evaluation_type/year (editing submitted records through a controlled, audit-trailed path is Story 1.8's scope).
5. The transition updates `status` and `updated_at`; no separate state-history table is created by this story.

## Tasks / Subtasks

- [ ] Define `SchedaStatus` enum (`draft`, `submitted`, `approved`) (AC: #1)
- [ ] Cast `Scheda.status` to `SchedaStatus`; confirm DB/model default is `draft` (AC: #1)
- [ ] Create `SubmitSchedaAction` validating all scores are present and in-range before transitioning (AC: #2, #3)
- [ ] Add "Submit" Filament action, visible only when `status = draft` (AC: #2)
- [ ] Guard `EditScheda` fields to read-only when `status != draft` (AC: #4)
- [ ] Feature tests: submit succeeds with complete scores; submit blocked with incomplete/out-of-range scores; edit form read-only after submit (AC: #2-#5)

## Testing

<!-- LOCKED. External dev tools must not edit Testing. -->

- **Unit:** `SchedaStatus` enum cases; model casts `status` correctly; factory-created records default to `draft`.
- **Feature:** submit action transitions status and persists it; submit blocked via validation when a score is null or out of `[1, 10]`; attempting to alter scores on a submitted record through `EditScheda` has no effect on the persisted row.
- **Fixtures:** `SchedaFactory` states `draft()` with complete scores, `draft()` with incomplete scores, `submitted()`.
- **Edge cases:** submitting an already-submitted record is a no-op (action not visible/available).
