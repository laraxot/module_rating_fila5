# Story 18.36 — Semplificare RatingData.php e creare RatingMorphData.php

## Il fatto

Durante la revisione del codice, è stato identificato che `laravel/Modules/Rating/app/Datas/RatingData.php` è eccessivamente complesso e non segue i principi di max DRY, max KISS, max clean code. Inoltre, manca un DTO dedicato per il pivot table `rating_morph` che sarebbe utile per gestire i dati del voto in modo consistente.

## La logica, prima del codice

Il file `RatingData.php` attualmente:
- Mescola due concetti diversi (DTO per il blocco UI e helper per lo schema della tabella)
- Ha un metodo `fromArray` eccessivamente verboso con controlli di tipo ridondanti
- Non sfrutta pienamente le capacità di Spatie Laravel Data per il casting automatico
- Manca una controparte specifica per il pivot table `rating_morph`

Applicando i principi BMAD e second brain:
1. **Separazione delle responsabilità**: Un DTO dovrebbe rappresentare un singolo concetto
2. **Massimizzare il riuso**: Sfruttare le funzionalità built-in di Spatie Data
3. **Semplicità**: Ridurre il codice boilerplate mantenendo la chiarezza
4. **Consistenza**: Seguire lo stesso pattern di altri componenti riusciti (es. DirittoColumn/DirittoSection)

## Proposta di implementazione

### 1. Semplificare `RatingData.php`
- Rimuovere il metodo `fromArray` personalizzato e fare affidamento sul casting automatico di Spatie Data
- Semplificare gli helper di schema mantenendo la stessa funzionalità
- Mantenere solo lo stretto necessario per rappresentare il blocco rating UI
