# Story 18.47 — Workflows Rating Module: Roadmap Completo

## Il fatto

In questa sessione si e' deciso di affrontare la risoluzione sistematica di **tutti i problemi critici** del modulo Rating, seguendo sempre gli stessi principi:

1. **BMAD** — ogni modifica porta alla creazione di una storia BMAD specifica
2. **Second brain** — coordinamento con altri agenti e validazione
3. **Pattern comune**: Usare sempre la base Xot (`XotBaseModel`, `XotBaseResource`) ed estenderla, mai estendere direttamente Filament
4. **Dati sacri** — no `migrate:fresh`, no `--force`, solo migrazioni additive
5. **PHPStan a 0 errori** — ogni modifica deve passare PHPStan senza warning
6. **Column Profile** — non usare mai `->label()` in UI (etichetta auto-tradotta)
7. **Adjacency list** — usare `staudenmeir/laravel-adjacency-list` per `parent_id` e hierarchie generatore-figlio
8. **CRUD consistente** — evitare sovrascritture `table()`; usare hook `HasXotTable`

## Principi applicati

### ✅ Max DRY
- `RatingData` e `RatingMorphData` condividono il pattern `addIfMissing()`
- `parent_id` e `children()` forniti dal trait, non riscritti
- `HasXotTable` centralizza hook del tavolo

### ✅ Max KISS
- Semplificato come richiesto (rimosso fromArray,
  sostituita con Spatie Data)
- i form sono un solo `BaseRatingForm`, nessun doppione

### ✅ Max clean code
- PHPStan 0 errori su ogni modifica
- Niente `->label()`
- Niente sovrascritture `table()`
- Niente `mixed` con tipi espliciti

### ✅ Adjacency list
- Usato `HasRecursiveRelationships` (vendor)
- `parent_id` come FK per gerarchie genitore-figlio
- `path` per ottimizzare query ricorsive

### ✅ CRUD consistente
- `BaseRatingResource` eredita `XotBaseResource`
- `BaseChildrenRelationManager` eredita `XotBaseRelationManager`
- Niente `->label()`
