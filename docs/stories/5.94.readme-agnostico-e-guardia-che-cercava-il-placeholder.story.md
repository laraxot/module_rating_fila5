# Story 5.94 — Il README nominava un'installazione

## Da dove nasce

Rilievo dell'utente il 2026-09-09:

> qui `laravel/Modules/Rating/README.md` parli di fixcity, tutti i moduli vengono
> utilizzati in piu' progetti, questo progetto non centra nulla con fixcity! i moduli
> devono essere agnostici

## Il fatto immediato

Il footer del README aveva **due righe identiche**, una delle quali con
`**Laraxot / FixCity Platform**`. Le due righe sono un residuo mio: risolvendo i conflitti
di un merge lasciato aperto da un'altra sessione, sui `.md` ho tenuto **entrambi i lati**
per non perdere prosa. Su un footer, che e' una riga sola ripetuta, quella scelta produce
un duplicato invece di un'unione.

Ora e' una riga sola:

```
**Modulo** `rating` · **Laraxot** · licenza MIT
```

Nemmeno il placeholder `<nome progetto>`: un modulo non appartiene a un progetto, quindi
nel footer non ci va ne' il nome ne' il suo segnaposto.

## Il difetto vero: la guardia era disattivata da se stessa

La regola esiste, e' completa e ha una guardia — `project-agnostic.md` e
`Modules/Xot/tests/Unit/Docs/ModuleDocsAreProjectAgnosticTest.php`, tetto decrescente.
Non ha visto niente, per due motivi indipendenti.

### 1. Cercava il placeholder invece dei nomi

```php
function hostProjectNames(): array
{
    return ['<nome progetto>', '<nome progetto>'];
}
```

E' la stringa con cui si **bonifica**. La guardia contava la cura invece della malattia:
restava verde e non poteva vedere nessun nome reale. Il suo stesso docblock dichiarava che
i nomi devono vivere li' — «elencarli in un documento agnostico sarebbe la violazione che
il documento vieta» — ma la regola e' stata applicata **al file della guardia**, che non e'
documentazione di modulo.

E' il caso generale che vale la pena ricordare: **una regola applicata al proprio
meccanismo di verifica lo disattiva**, e lo fa senza rumore, perche' il test resta verde.

### 2. Il perimetro escludeva i README

```php
if (! str_contains($path, '/docs/')) {
    continue;
}
```

`Modules/*/README.md` era fuori dal controllo: il primo file che si legge quando un modulo
viene riusato altrove.

## Le misure

Con i nomi reali, su `Modules/` e `Themes/`, esclusi `vendor/`, `node_modules/`,
`graphify-out/`:

| | file `.md` |
|---|---:|
| totale che nominano un'installazione | **1125** |
| di cui sotto `/docs/` (vecchio perimetro) | 1117 |
| di cui **README** (fuori dal vecchio perimetro) | **17** |

Per nome: `ptvx` 596, `saluteora` 380, `fixcity` 57, `quaeris` 38.

Il nome piu' scritto e' quello del progetto **corrente**. E' la trappola vera: mentre si
lavora qui, scrivere «ptvx» sembra naturale e la frase e' persino vera. Diventa falsa il
giorno dopo, altrove.

Per confronto, il vecchio tetto (1642) contava i file contenenti il **placeholder**, che
sono 3254 sotto `/docs/`: due numeri che non misuravano la stessa cosa.

## Cosa e' stato fatto

| | |
|---|---|
| `Modules/Rating/README.md` | footer deduplicato e senza nome di progetto |
| `hostProjectNames()` | nomi reali: `fixcity`, `ptvx`, `saluteora`, `quaeris` |
| perimetro della guardia | ogni `.md` di modulo/tema, non solo `/docs/` |
| tetto | rimisurato a **1125** |

Verifica: `./vendor/bin/pest Modules/Xot/tests/Unit/Docs/ModuleDocsAreProjectAgnosticTest.php`
→ **2 passed**.

## Cosa NON fa questa story

Non bonifica i 1125 file. Il tetto impedisce che il numero salga, che e' la parte
applicabile subito; la bonifica e' materia della discussion #52, dove ci sono due decisioni
aperte: sostituzione meccanica o per moduli, e se il placeholder sia sempre la forma giusta
(nel footer non lo e').
