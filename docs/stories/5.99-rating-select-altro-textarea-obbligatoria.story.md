# Story

Quando un `rating` (criterio) ha figli, `buildRatingComponent()` costruisce un `Select` con le
opzioni = figli. Va aggiunta un'opzione "altro"; se l'utente la seleziona, appare una `Textarea`
obbligatoria il cui valore va salvato.

**Questa story è la visto di implementazione. La specifica di design (pseudocodice, decisioni
D-1..D-6, motivazioni) è SSoT in `rating-altro-option-conditional-textarea-design.story.md`** —
stessa epic 5, stessa feature. Qui sotto: riepilogo operativo, punti "fatto quando" e test.

# Stato attuale del codice

File: `laravel/Modules/Rating/app/Models/Traits/HasRatingsTrait.php`

```php
// Linea 260-263: il nome del campo via sistematico
public static function ratingFieldName(BaseRating $rating): string
{
    return 'ratings.'.$rating->id.'.pivot.value';
}

// Linea 343-373: build del componente (privato)
if ($rating->is_readonly === true) {
    return TextEntry::make($field)->inlineLabel();
}

$options = $rating->children
    ->mapWithKeys(static fn (BaseRating $child): array => [$child->id => $child->getLabel()])
    ->all();

$component = $options === []
    ? TextInput::make($field)->numeric()->live(onBlur: true)
    : Select::make($field)->options($options)->live();

return $component
    ->nullable()
    ->inlineLabel()
    ->rules((string) ($rating->rule->value ?? ''))
    ->afterStateUpdated(
        static function (Set $set, Get $get) use ($caller, $readonlyRatings): void {
            $caller?->recalculateRatingFields($set, $get, $readonlyRatings);
        }
    );
```

Le opzioni del `Select` sono **solo** id interi dei figli: non esiste oggi alcuna chiave
`''`/`null` e non va creata (vedi Decisione 1: sentinella stringa `'altro'`).

# Piano di implementazione (segue la SSoT, non la riscrive)

1. **Sentinella** — costante privata sul trait:
   `private const string ALTRO_KEY = 'altro';`
2. **Nome campo nota** — estendere `ratingFieldName(BaseRating $rating, string $pivotColumn = 'value')`
   (retrocompatibile; le chiamate esistenti restano su `pivot.value`, la nuova è
   `ratingFieldName($rating, 'note')` → `ratings.{id}.pivot.note`).
3. **Salvataggio** — colonna `rating_morph.note` (già esistente, `text` nullable, sia nella
   migration 2026_07_27:30 sia nella 2026_07_15:48 con guardia `hasColumn`). **Nessuna migration**
   e nessun nuovo import di storage: il payload `ratings.{id}.pivot.note` viaggia come il
   `pivot.value` esistente tramite lo stesso meccanismo (verificare in sede d'implementazione
   che il sync del pivot dell'host lo propaghi; oggi `PrepareCompilaDataAction:35` fa
   `syncWithoutDetaching($ratingsForYear->pluck('id'))`).
4. **Label dell'opzione** — `trans('rating::fields.altro')` come **valore** dell'opzione
   nell'array `$options` (NON `->label()` su un componente: vincolo D-1 della story 5.92).
   Aggiungere la chiave a `Modules/Rating/lang/it/fields.php` (e altre lingue presenti).
5. **Coda comune solo sul Select** — `nullable/inlineLabel/rules/afterStateUpdated` restano sul
   `Select`; il `Group` che avvolge Select+Textarea non riceve `rules()`/`nullable()`.
6. **Textarea condizionale** — nello stesso confronto:
   ```php
   $note = Textarea::make(self::ratingFieldName($rating, 'note'))
       ->visible(static fn (Get $get): bool => $get($field) === self::ALTRO_KEY)
       ->required(static fn (Get $get): bool => $get($field) === self::ALTRO_KEY);
   ```
   Nessun `->maxLength()`.
7. **Ritorno** — `return Group::make([$select, $note]);`
   (`Filament\Schemas\Components\Group` verificato esistente; compatibile col tipo di ritorno
   `Component` di `buildRatingComponent()`).
8. **`getRatingsFormSchema()`** — nessuna modifica: indicizza `$schema[self::ratingFieldName($rating)]`
   col componente (ora un `Group`), `decorateRatingField()` lo riceve intero.
9. **`RatingsFormCallerContract`** — nessun nuovo metodo.
10. **`recalculateRatingFields()`** — non reagisce alla `note` (storage descrittivo, non business).

# Fatto quando

- [ ] `ALTRO_KEY` privata `'altro'` sul trait
- [ ] `ratingFieldName()` con parametro `$pivotColumn = 'value'` (retrocompatibile)
- [ ] `trans('rating::fields.altro')` aggiunta a `lang/*/fields.php`
- [ ] Coda su `Select`, non sul `Group`
- [ ] `Textarea` su `pivot.note`, `visible()`+`required()` su `=== ALTRO_KEY`, senza `->maxLength()`
- [ ] `RatingsFormCallerContract` invariato
- [ ] Nessuna migration
- [ ] Nessun `->label()` nel trait
- [ ] Test Pest PRIMA (TDD): opzione "altro" presente, textarea nascosta di default, visibile
      dopo selezione "altro" (via `live()`), required solo quando visibile, valore salvato su
      `pivot.note`, rating readonly / senza figli invariati
- [ ] PHPStan livello 10 (0 errori, baseline), Pint, PHPMD, PHPInsights

# Comportamento atteso (test manuali di riferimento)

- Select con figli: appare l'opzione "altro" in coda alle opzioni reali
- Selezione "altro" → la Textarea diventa visibile ed è obbligatoria
- Testo vuoto con "altro" selezionato → errore di validazione
- Opzione valida (`id` figlio) → Textarea nascosta, non richiesta, `pivot.value` salvato
- Sul salvataggio, il testo di "altro" atterra su `rating_morph.note`
